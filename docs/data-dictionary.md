# Catalyst Observability Data Dictionary

> Single source of truth for the **metrics, logs, and traces** flowing through the catalyst observability stack (OTel Collector → Prometheus + Loki + Tempo → Grafana). Use it to know what each signal means, which dimensions you can trust, and how to correlate across signals.
>
> **Last verified:** 2026-06-29 against the live home stack. **Owner:** OTL team. When you add/rename a signal or dimension, update this file (a CI governance check is planned — see [Data quality](#data-quality--desired-envelope)).

## How to query

| Signal | Store | Grafana datasource (uid) | Direct query via proxy |
|---|---|---|---|
| Metrics | Prometheus | `prometheus` | `https://otel.rozich.com/api/datasources/proxy/uid/prometheus/api/v1/...` |
| Logs / events | Loki | `loki` | `.../uid/loki/loki/api/v1/...` |
| Traces | Tempo | `tempo` | `.../uid/tempo/api/search?q={}` |

- **OTel → Prometheus naming:** dots → underscores; counters get a `_total` suffix (`claude_code.cost.usage` → `claude_code_cost_usage_USD_total`).
- **Loki labels:** only `service_name` + `service_namespace` are **stream labels** (selectors). Everything else (`host_name`, `event_*`, `catalyst_node_name`, …) is **structured metadata** — filter with `| field="x"`, aggregate with `sum by (field)`, but `/label/<x>/values` returns empty. Don't `| json` a body unless it IS json (the CTL-1330 daemon `.log` lines now ship full-json bodies; most events carry fields as structured metadata, not in the body).
- **At-rest expiry:** `signal_to_metrics` gauges vanish ~15m after their source stops sampling (`metric_expiration: 15m`); counters persist.

## Common dimensions & cross-signal correlation

**The one reliable way to correlate metrics ↔ logs ↔ traces is service identity:**
- **`service.name`** (`service_name`) — clean dotted form everywhere (`catalyst.execution-core`, `catalyst.broker`, `claude-code`, …). THE join key.
- **`service.namespace`** (`service_namespace`) — clean `{catalyst, conductor}`; also a Loki stream label (cheapest selector). Pair with `service.name` for unambiguous service joins.

Full reliability matrix:

| Dimension | Present in | Reliability | Note |
|---|---|---|---|
| `service.name` / `service_name` | metrics, logs, traces | ✅ reliable | THE cross-signal join key. Now live on traces too (`catalyst.execution-core`, CTL-1330). |
| `service.namespace` / `service_namespace` | metrics, logs, traces | ✅ reliable | Clean `{catalyst, conductor}`; Loki stream label. Now on traces too (CATALYST added it 2026-06-24). |
| `host_name` | metrics, logs | ⚠️ partial | Clean SHORT in metrics; **split FQDN/short in logs** (see below). Joinable for catalyst.* only. |
| `hostname` | metrics, logs | ❌ broken | 2nd host dim; chaotic OS aliases (one machine = many names); sole host signal on claude_code metrics. |
| `catalyst_node_name` | logs only | ❌ broken | 3rd host dim; ~86% empty; never a metric label. |
| `host_id` | metrics only | ⚠️ partial | Cleanest host key *within* metrics (1:1 with host.name) but metrics-only. |
| `instance` | metrics only | ❌ broken | **NOT a host** — the Prometheus scrape target `otel-collector:8889`. `service.instance.id` is unset everywhere. |
| `job` / `exported_job` | metrics only | ⚠️ partial | `job` = constant scrape artifact; `exported_job` re-encodes namespace/service. |
| `environment` | metrics, logs, traces | ⚠️ partial | Reaches all 3 but only `production` is consistent (metrics also carry a `dev` slice). |
| `linear_key` | metrics, logs | ⚠️ partial | Joinable for context-stamped sessions when direnv `use_otel_context` is active. |
| `project` / `branch` | metrics only | ❌ broken | Not promoted to logs/traces — can't correlate cross-signal. |
| `session_id` | metrics, logs | ⚠️ partial | Most precise metrics↔logs join but ~23k cardinality — drill-down only, never a label. |
| `service.version` | metrics | ⚠️ partial | 89 distinct values, per-deploy churn — facet, not a join key. |
| `catalyst_node_class` | metrics, logs | ⚠️ partial | Fleet role `{developer, worker, monitor}` (CTL-1368; default `worker` when unset). Stamped on every catalyst signal as resource attr `catalyst.node.class` → label `catalyst_node_class` (NOT bare `node_class` — dashboard vars must key the prefixed name). Reusable node-class facet/template var; orthogonal to host identity (`host.name`=which machine, `node.class`=what role). |

**Host identity is the biggest gap (verified 2026-06-24).** `host_name` is clean short (`mini`/`mini-2`) in metrics but **split in logs** over 24h:

| `host_name` (catalyst logs) | lines |
|---|---|
| `mini-2.rozich` | 100,177 |
| `mini-2` | 63,384 |
| `mini.rozich` | 47,446 |
| `mini` | 25,430 |

~62% FQDN → **logs↔metrics won't join on host today.** Join catalyst metrics↔logs on `host_name` only within `catalyst.*` and only the short form; for everything cross-signal use `service.name`/`service.namespace`. The fix is tracked in [Data quality](#data-quality--desired-envelope).

## Gotchas (read before trusting a query)
- **Counters vs gauges:** `*_total` are counters → always `rate()`/`increase()`, never raw. The ~29 `signal_to_metrics` gauges are last-value and expire ~15m at rest; the OTL-31 scheduler-health histograms (tick/pass/api_request/install duration) carry an implicit `le` label.
- **`linear_key` on `catalyst_event_total`** is present as a label (bounded ~13 values) though the OTL-20 spec forbade it — the cardinality-growth risk to watch.
- **`instance` is a red herring** (the collector scrape target, not a producer). **`job`** is constant; use `exported_job`.
- **Two load/memory views:** `catalyst_scheduler_*` (autotuner) vs `catalyst_host_*` (agent host-sampler) differ by sampler/timing — not interchangeable (OTL-26/27).
- **Traces are LIVE (2026-06-24):** real `catalyst.execution-core` spans flow (CTL-1330) — `scheduler.tick` root + `scheduler.pass` children, carrying `service.name`, `service.namespace`, short `host.name`, `catalyst.node.name`, `environment`. Caveat: trace↔logs correlation does **not** round-trip yet (three disjoint id spaces — see Traces catalog → Correlation); `filterByTraceID:false` is the interim, OTL-30 ⇄ CTL-1337 the real fix.

## Data quality & desired envelope
Cross-signal correlation is reliable only on **service identity**; **host identity is broken** (details above). Tracked in **OTL-29** (collector-side host canonicalization + dimension governance) and a sibling catalyst (CTL) cleanup ticket (producer-side daemon-`.log` host fix); metric-value divergence in **OTL-26 / OTL-27**.

**Desired "common envelope"** — every signal carries the same canonical resource set, one value form each:
`service.name` (dotted) · `service.namespace` · `service.version` · `service.instance.id` *(add)* · **`host.name` = ONE short form** *(deprecate `hostname` + `catalyst_node_name`)* · `host.id` · `deployment.environment`. **Traces must additionally carry `host.name` + `service.namespace`.**

**Fix split:** collector-chokepoint OTTL host normalization (OTL — retroactive, covers third-party Claude Code) + producer-side daemon-`.log` host fix (catalyst). Reconcile metric-value divergence with OTL-26/OTL-27.

### Context Engine — index host reindex (catalyst-cloud; `service_name=catalyst-cloud.index-host`)

> **Self-serve report-builder spec — read this first.** The reindex signal is **two coupled artifacts, NOT a metric**: (a) a Loki completion log `index.run.complete` under `service_name=catalyst-cloud.index-host` / `service_namespace=catalyst-cloud`; and (b) a Tempo trace rooted at span `index.run` with per-phase children. **There is NO Prometheus connector for index-host** (contrast `catalyst_install_*`, which DOES have a `count` + `signal_to_metrics` pair) — so **100% of counts, cost, latency come from Loki/Tempo, never Prometheus.** `service_name` + `service_namespace` are the **ONLY Loki stream labels** (the cheap selectors *and* the cross-store join anchor); **everything else is structured metadata** (filter `| f="v"`, aggregate `sum by (f)` — `label_values(f)` returns EMPTY). > In the patterns below, **`‹idx›`** = `{service_name="catalyst-cloud.index-host"} |= "index.run.complete" != "json-probe"` (the de-probed run-completion stream).

### Resource attributes (all catalyst spans)

Every catalyst span carries OTel-semconv resource attributes, set in daemon code and serialized in the OTLP trace payload (a separate channel from the pino→Loki log path):

- **service.name** (REQUIRED, semconv) — one of `catalyst.execution-core` (scheduler.tick / scheduler.pass / liveness.refresh), `catalyst.broker` (broker.route), `catalyst.monitor` (monitor HTTP). These strings are deliberately IDENTICAL to the Loki `service_name` values — the Tempo datasource maps span service.name → Loki service_name to power the 'Logs for this span' jump, so trace↔logs correlation fires only because the names match. Do NOT use a traces-specific namespace.
- **host.name** (semconv) — distinguishes mini from mini-2. host.name is a RESOURCE attribute ONLY — never also put it on a datapoint/span attribute (the prometheus exporter's `resource_to_telemetry_conversion` treats a duplicate label as a collision and silently drops the metric — the OTL-20 landmine).
- **catalyst.node.name** (catalyst-custom) — the catalyst fleet node id carried alongside host.name; the join key used across logs/metrics for per-node aggregation.
- **Collector addition:** the resource processor stamps `environment=production` on every span (observed on the live smoketest trace).
- **Correlation (does NOT round-trip yet — verified 2026-06-24):** the original premise (trace_id stamped on logs → correlation lights up automatically) is **false in practice** because there are **three disjoint id spaces**: (1) Tier-3 SPANS get SDK-random trace_ids (Tempo has them); (2) canonical EVENTS carry deterministic `canonical-event-shared.ts` trace_ids — but those are derived **per-orchestrator** (`sha256(orchestratorId)`), and Tempo 404s on them (never emitted as spans); (3) the Tier-1 tick-timing `.log` line carries **no** trace_id at all. The span ids and the log/event ids never coincide, so neither direction round-trips. Interim sink fix shipped: `filterByTraceID:false` (tracesToLogsV2 scopes "Logs for this span" by service.name + a ±1m window — degraded but useful). The real fix (one deterministic **per-tick** trace_id stamped on both span + tick-timing log) is the tracked fast-follow **OTL-30 ⇄ CTL-1337**; it also unblocks Prometheus exemplars (bucket → flame-graph). Tempo datasource (uid `tempo`) is provisioned with tracesToLogsV2 (→ Loki) and Loki derivedFields on trace_id (logs → traces), 14-day retention.
